# 급여명세 장부 (v1.2.0)

나이스(NEIS) 급여명세서 PDF·Excel을 월별로 모아 보고 비교하는 개인용 웹앱입니다.
모든 처리는 브라우저 안에서 이루어지며, 파일과 급여 데이터는 외부로 전송되지 않습니다.

## 1. 설치 (GitHub Pages 기준)

1. GitHub에서 새 저장소를 만듭니다. **급여 데이터는 저장소에 올라가지 않으므로** 공개 저장소여도 앱 파일만 공개됩니다.
2. 이 폴더(`salary-app`) 안의 파일을 모두 저장소 최상위에 올립니다.
   - `tests/` 폴더는 올리지 않아도 됩니다.
3. 저장소 → Settings → Pages → Branch를 `main` / `root`로 지정하고 저장합니다.
4. 1~2분 뒤 표시되는 `https://아이디.github.io/저장소명/` 주소로 접속합니다.
5. 스마트폰에서 홈 화면에 추가합니다.
   - iPhone(Safari): 공유 버튼 → **홈 화면에 추가**
   - Android(Chrome): 메뉴 → **앱 설치** 또는 **홈 화면에 추가**

> PWA(홈 화면 앱, 오프라인 실행)는 **https 주소**에서만 동작합니다.
> 파일을 더블클릭해서 여는 방식(`file://`)으로는 PDF 분석과 저장이 제대로 되지 않습니다.

### PC에서 임시로 실행하기
```
cd salary-app
python -m http.server 8000
```
브라우저에서 `http://localhost:8000` 접속.

## 2. 앱 잠금(PIN)

- 처음 열면 **숫자 4자리 PIN**을 정합니다. 이후 앱을 새로 열 때마다 PIN을 묻습니다.
- 저장된 기록은 PIN에서 만든 키로 **암호화(AES-256-GCM, PBKDF2 60만 회)**됩니다. PIN 자체는 저장하지 않습니다.
- 앱을 **완전히 종료**하거나 상단 **잠그기** 버튼을 눌러야 잠깁니다. 홈 화면으로 나가기만 하면 잠기지 않습니다.
- PIN을 4번 이상 틀리면 30초부터 최대 15분까지 입력이 막힙니다. 기록이 자동 삭제되지는 않습니다.
- **PIN을 잊으면 기록을 되살릴 수 없습니다.** 잠금 화면의 "PIN을 잊었어요 → 앱 초기화" 후 백업으로 복원하세요.
- 이전 버전(v1.0)에서 저장한 기록은 PIN을 처음 정할 때 자동으로 암호화됩니다.

### 보안 수준에 대한 솔직한 안내
- 4자리 PIN은 경우의 수가 1만 개입니다. 휴대폰을 잠깐 만지는 사람은 막지만, **기기나 백업 파일을 확보한 사람이 전문 도구를 쓰면 짧은 시간에 풀 수 있습니다.**
- 따라서 **휴대폰 화면 잠금**을 반드시 켜고, **백업 파일은 본인만 접근하는 곳**에 보관하세요.

## 3. 연도 비교 (v1.2.0)

하단 메뉴 **비교**(PC에서는 "연도 비교")에서 두 해를 나란히 비교합니다. 두 해 이상의 기록이 있어야 표시됩니다.

- **비교 기준 전환**
  - 같은 달끼리: 두 해 모두 기록이 있는 달만 비교합니다(권장).
  - 연간 합계: 각 해에 저장된 모든 달을 합산합니다. 개월 수가 다르면 경고가 표시됩니다.
- **연도 간 증감**: 급여·세금·공제·실수령액과 월평균 실수령액의 증감액·증감률, 전체 연도 실수령액 추이
- **같은 달 연도 비교**: 1~12월에 연도별 선을 겹쳐 표시(최근 5개 연도, 항목 선택 가능)
- **항목별 연간 비교**: 각 급여·세금·공제 항목의 합계 비교, 신규·없어진 항목 표시
- **세금·공제 부담률 추이**: 급여총액 대비 세금·공제 비율
- **같은 기간 누적 비교**: 1월부터 선택한 달까지, 두 해 모두 기록이 있는 달만 누적

## 4. 데이터에 관한 중요 안내

- 기록은 **접속한 브라우저의 저장소(IndexedDB)**에만 있습니다. 휴대폰과 PC의 기록은 서로 공유되지 않습니다.
- 브라우저의 "사이트 데이터 삭제"를 하면 기록도 지워집니다. **데이터 관리 → 백업**을 정기적으로 받아 두세요.
- 다른 기기로 옮길 때는 백업 JSON을 그 기기에서 **복원**합니다.
- 백업 파일은 **백업을 만든 시점의 PIN**으로 암호화됩니다. 복원할 때 그 PIN이 필요합니다(PIN을 바꾼 뒤라도 옛 백업은 옛 PIN으로 엽니다).
- 백업 파일은 4자리 PIN으로만 보호되므로 메신저·메일로 주고받지 마세요.
- 성명, PDF 하단의 접속 정보(IP·출력 시각)는 읽거나 저장하지 않습니다.

```

js/extractors.js      파일 → 표 격자 (PDF: 셀 사각형+글자 좌표 / Excel: 병합 셀)
js/parser.js          표 격자 → 급여 기록, 계산근거 분해, 검증
js/data.js            암호화·PIN 잠금, IndexedDB 저장, 분석, 백업·복원
js/ui-common.js       공통 화면 도구, 차트
js/editor.js          추출 결과 확인·수정 편집기
js/views.js           홈·업로드·월별·연도별·데이터 관리 화면
js/app.js             화면 전환, 서비스워커 등록
lib/                  pdf.js 3.11.174, SheetJS 0.18.5, Chart.js 4.4.4 (외부 CDN 미사용)
tests/                파서 회귀 테스트 (배포 불필요)
```

## 6. 나이스 양식이 바뀌었을 때

파서는 셀 좌표가 아니라 **라벨**을 기준으로 값을 찾습니다.
`급여지급년월`, `급여내역·세금내역·공제내역`, `급여총액·세금총액·공제총액`, `실수령액`, `계산근거`, 기본정보 라벨.

- 라벨 이름이 바뀌면 `js/parser.js`의 `BASIC_LABELS`, `GROUPS`만 고치면 됩니다.
- 수정 후 `sw.js`의 `VERSION` 숫자를 올려야 설치된 앱이 새 파일을 받습니다.
- 수정 전후로 `tests/`의 회귀 테스트를 실행해 기존 명세서 결과가 그대로인지 확인하세요.

### 회귀 테스트 실행 (Node.js 18 이상)
```
cd tests
npm install pdfjs-dist@3.11.174 xlsx@0.18.5
node run-tests.js <명세서 파일 폴더>
```
`tests/expected/`에 들어 있는 기준 결과(2026년 8월·9월)와 비교합니다.
새 달의 명세서를 폴더에 넣고 실행하면 그 달의 기준 결과가 자동으로 추가됩니다.

## 8. 알려진 한계

- 연도별 분석의 호봉·근무년수 그래프는 v1.1에서 삭제했습니다(월별 표와 변동 사항 목록에서 확인).
- 지문·Face ID 잠금은 지원하지 않습니다.
- 이미지(스캔) PDF는 읽지 않습니다. 나이스 원본 PDF 또는 Excel을 사용하세요.
- 호봉·보직이 바뀐 달의 실제 명세서로는 아직 검증하지 않았습니다.
- 본봉 계산근거의 `교원봉급표적용` 문구는 항목으로 나누지 않고 원문으로만 보관합니다.
- SheetJS 0.18.5는 npm에서 받을 수 있는 마지막 버전이며, 악의적으로 조작된 엑셀 파일에 대한 알려진 취약점이 있습니다. 본인이 나이스에서 받은 파일만 올리는 용도라면 위험은 낮습니다.
